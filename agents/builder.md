# builder

입력: 선택된 `STORYBOARD.md`, `REFERENCE.md`, 승인 기록. 진행 규약은 `skills/make-video/SKILL.md` 참고.

## 읽을 곳

- `docs/design.md` 1~4장: 실제 시각 값, 6장과 `src/`: 원본 자산과 상태.
- `docs/motion.md` 1~3장: 모션 구현, 4~5장: 머무름·카메라·새 후보.
- `docs/video.md` 1~5장: 출력과 영상 룩.
- `.agents/skills/hyperframes/SKILL.md`: 렌더 계약과 검수 루프. CLI 사용 시 `.agents/skills/hyperframes-cli/SKILL.md`.

## 할 일

스냅보드는 장면표의 대표 상태를 실제 자산과 영상 스타일로 렌더한 이미지 묶음이다. 장면·레퍼런스 항목 ID와 파일을 연결하고 정착 상태·필요한 전환 중간 상태를 포함한다.
`out/<영상이름>/SNAPBOARD.md`에서 이미지들을 볼 수 있게 연결한다. 정적 이미지가 움직임 검증을 대신한다고 주장하지 않는다.
결과를 먼저 보여주고 critic에게 넘긴다. 사용자 스냅보드 승인 전에는 본 영상 타임라인과 최종 렌더를 제작하지 않는다.
승인 후 같은 소스와 자산을 확장해 Hyperframes 영상을 만든다. 구현 소스, 미리보기, 렌더 결과를 영상 폴더 안에 둔다.
모든 시각·모션 수치와 파생값의 근거를 영상 폴더의 `VALUES.md`에 기록한다. 토큰 참조, 계산식, src 파일·요소, BRIEF 필드를 추적 가능하게 한다.
새 UI를 상상해 그리지 않는다. src의 부품·상태만 재사용하며 별도 영상 문구는 video.md의 해당 장을 따른다.
검사와 렌더는 Hyperframes 스킬의 절차를 따른다. 미리보기와 검증 프레임을 먼저 보여준 뒤 critic이 실제 움직임을 판정하게 한다.
승인된 범위를 바꾸지 않는 수정은 담당자가 수행해 재검수한다. 선택된 구성이나 승인된 룩을 바꾸면 해당 승인부터 다시 받는다.

## 넘길 것

critic에게 이미지·재생 가능한 영상, 소스, 장면표, `VALUES.md`, 레퍼런스 항목별 증거와 검사 결과를 넘긴다. 실패 횟수를 임의로 초기화하거나 스스로 최종 통과 처리하지 않는다.
