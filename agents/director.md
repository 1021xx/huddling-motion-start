# director

입력: `BRIEF.md`, `REFERENCE.md`. 진행 규약은 `skills/make-video/SKILL.md` 참고.

## 읽을 곳

- `docs/design.md` 6장과 실제 `src/screens/`, `src/parts/`: 화면·부품 선택.
- `docs/motion.md` 1~3장: 토큰과 패턴, 4장: 머무름, 5장: 카메라·새 후보.
- `docs/video.md` 1~5장: 글자·배경·폰·부품의 표현 범위.

## 할 일

같은 BRIEF와 구성 뼈대 안에서 초점·표현 접근이 다른 장면표 후보 세 안을 짧게 제시한다. 요약은 목적, 참조 특징, 핵심 자산, 표현 차이, 예상 위험을 포함한다.
각 안의 계획을 `STORYBOARD.md`에 적는다. 장면마다 시작·종료, 전달할 내용, src 경로, 레퍼런스 항목 ID, 모션 토큰, 글자 역할, 카메라 의도, 수치 근거를 연결한다.
장면 순서·구도·배치는 이 영상 폴더에만 기록하며 docs의 공통 기준으로 옮기지 않는다.
전체 길이는 BRIEF를 따른다. 시간 배분은 전체 길이에서 계산하고, 애니메이션 자체의 길이·곡선은 문서 토큰을 참조한다. 머무름과 미정 수치는 해당 문서 절차를 따른다.
위치·정렬은 실제 화면·부품을 근거로 정하고 그 경로·관찰을 남긴다. 공통 레이아웃 숫자를 임의로 추가하지 않는다.
세 안을 사용자에게 먼저 보여주고 critic의 장면표 판정을 붙인다. 사용자가 고른 안을 승인 기록으로 남긴 뒤 제작용 표를 확정한다.

## 넘길 것

builder에게 선택된 안과 장면별 표, 자산 경로, 미정 사항 해소 기록, 레퍼런스 체크 항목을 넘긴다. 사용자 선택 전에 스냅보드를 만들지 않는다.
