# 디자인·모션 품질 검수

규칙을 지킨 영상과 잘 설계된 영상을 구분한다. 한 축의 통과로 다른 축의 실패를 상쇄하지 않는다. 자동 검사는 기술·가독성 결함을 찾는 보조 수단이며 미적 만족의 판정기가 아니다.

## 1 브랜드·사실
[brand-rules.md](brand-rules.md)를 대조한다. 원본 훼손, 가상 서비스 기능, 잘못된 수치, 사용자 조건 위반을 확인한다. 영상용 새 그래픽과 실제 UI를 구분한다. 문서에 없는 연출 숫자 자체는 오류가 아니다.

## 2 정적 디자인
대표 정착 프레임을 실제로 본다. 다음 질문마다 관찰과 수정 필요성을 남긴다.
- D1 주인공: 한눈에 무엇부터 봐야 하는가? 제목·UI·장식이 경쟁하지 않는가?
- D2 구성: 여백·정렬·크기 대비가 의도적으로 잡혔는가? 화면 한쪽이 이유 없이 비거나 붐비지 않는가?
- D3 일관성: 타이포·그림자·원근·그래픽 재질이 하나의 룩을 만드는가?
- D4 정보: 카피가 짧고 읽히는가? 예시 이미지와 설명의 의미가 맞는가?
- D5 변화: 같은 구도를 반복하지 않으면서도 장면 사이에 시각적 일관성이 있는가?

정적 구도가 부족하면 모션 추가로 덮지 말고 스냅보드부터 수정한다. 특정 수치나 효과 유무를 미적 품질의 대리 점수로 쓰지 않는다.

## 3 움직임과 편집
정착 이미지와 별도로 전환 구간을 확인한다. 실제 재생을 볼 수 있으면 전체 흐름을 보고, 연속 프레임은 경계·가림·튀는 움직임 확인에 쓴다. 재생을 확인하지 못했다면 관찰 범위와 남은 불확실성을 적는다.
- M1 연결: 앞 장면의 대상·방향·위치·행동 중 무엇이 다음 장면으로 이어지는가?
- M2 리듬: 다음 정보가 너무 늦게 오거나, 읽기 전에 사라지는가? 빈 시간을 장식적 반복으로 채우지 않았는가?
- M3 집중: 움직임이 시선을 이끄는가? 여러 대상이 동시에 주의를 요구하지 않는가?
- M4 마감: 감속·정착·퇴장·전환 경계가 자연스러운가? 글자 잘림과 유령 레이어가 없는가?

모든 컷을 같은 길이로 자르거나 모든 순간을 움직이게 하는 것이 목표가 아니다. 긴 정지에도 읽기·강조 목적이 있으면 허용한다.

## 4 기술
최종 파일의 해상도·fps·길이·자산/폰트 로드·프레임 누락·불필요한 빈 화면·음향 조건을 확인한다. 렌더러 검사 후 최종 인코딩 파일에서도 대표 프레임과 주요 전환을 확인한다. 의도된 겹침과 실제 결함을 구분한다.

## 5 참고 표현의 반영
REFERENCE.md의 핵심 원리마다 `관찰한 사실 → 적용 의도 → 결과의 시점/프레임 → 반영 여부`를 기록한다. 확인하지 않은 영상의 동작·숫자는 지어내지 않는다. 단순 등장·감속·시차 충족 개수나 일률적인 반영률로 디자인을 통과시키지 않는다. 참고와 달리 적용했다면 그 목적을 설명한다.

## 판정

### 수정 후 문서 반영 — 완료 조건

수정을 완료했다고 보고하기 전에 docs 반영을 확인한다. 버전 README나 대화에만 남기고 끝내지 않는다.

1. 수정의 원인, 재발 방지 규칙, 확인 방법을 해당 docs에 기록한다. 브랜드·사실은 brand-rules.md, 연출 원칙은 motion-direction.md, 검수 방법은 이 문서로 분리한다.
2. 버전 한정 수치·좌표·타이밍·효과 선택은 영상별 문서에 남긴다. 이를 공통 규칙으로 확대하지 않는다. 공통 docs에는 해당 선택을 판단하는 원칙을 기록한다.
3. 기존 규칙으로 충분한 수정은 같은 규칙을 중복 추가하지 않는다. 수정 기록에 적용한 규칙과 검증 결과를 연결한다.
4. 원본 프로젝트의 docs와 전달용 문서 사본을 함께 갱신하고 일치 여부를 확인한다. 최종 응답에는 실제 갱신한 문서만 안내한다.

### 전환·효과 구현에서 재발 방지

- 버튼 줌 전환은 클릭 직전·확대 시작·화면 채움의 연속 프레임을 비교한다. 원래 버튼 옆에 새 도형이 생기거나 경계가 튀면 실패다.
- 엔딩에서는 마지막 정보가 나타난 시점부터 끝까지의 잔여 시간을 확인한다. 읽기 목적 없는 긴 정지는 축소하고, 로고와 타이포의 겹침·잘림을 확대 중에도 검사한다.


- 정착 프레임만 보지 않고 제목 교체·카메라 이동 중간을 확인한다. 이동 중인 카드와 새 제목이 겹치면 위치 또는 등장 시점을 수정한다.
- 파티클 등의 생성 개수와 타임라인 대상 개수가 일치해야 한다. 실행 오류가 0이어도 missing target 경고를 방치하지 않는다.
- 수치와 바의 시작·중간·끝 프레임을 비교한다. 서로 다른 easing으로 같은 진행 상태가 다르게 보이지 않도록 한다.
- 새 버전을 만들 때 보존 대상 소스와 렌더 파일의 변경 여부를 확인한다.

REVIEW.md에 `브랜드·사실 / 정적 디자인 / 움직임·편집 / 기술`을 각각 PASS·수정 필요·미검증으로 적는다. 문제별 ID, 파일·시점, 관찰 근거와 수정 방향을 남긴다. 단계상 아직 없는 결과는 해당 없음으로 표시한다.

최종 기술 오류나 전달을 방해하는 디자인·모션 결함은 수정한다. 미검증을 PASS로 바꾸지 않는다. 담당자가 판단 가능한 수정을 먼저 수행하고, 사용자 취향 선택이나 조건 충돌이 있어야 질문한다. 사용자 평가는 검수자의 PASS와 별개로 기록한다.
