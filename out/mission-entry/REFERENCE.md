# 레퍼런스 정리 — v1

## 출처와 역할

- **뼈대 R**: [Remotion Prompts — Apple-Style Device Rise Animation](https://www.remotion.dev/prompts/apple-style-device-rise-animation), `Prompt` 절. 페이지를 다시 열어 본문 확인. 실제 재생 영상은 측정하지 않았다. 아래 근거는 모두 문서 지시이며 타임코드 없음.
- **보조 C**: [Carbon Design System — Motion](https://carbondesignsystem.com/elements/motion/overview/), `Style`, `Easing`, `Duration tokens`. 값은 `docs/motion.md`의 기존 정의를 사용한다.
- 구성 원리: 기기 등장과 정착 → 카드의 시차 등장. 이를 미션 참여의 각 설명 단위에 반복 적용한다. 미션·제출·승인의 의미 순서는 BRIEF에서 온다.
- 구도: R의 중심 피사체를 기준으로 세로 화면을 시각적 기준점으로 유지한다. 별도 영상 헤드라인은 서비스용 적용이며 레퍼런스 관찰로 점수화하지 않는다.
- 카메라: R 본문은 피사체 회전·스케일 지시다. 카메라 이동 실측 근거 없음. 이번 제안은 `docs/motion.md` 5장의 고정 시점.

## 반영 체크 항목 — 제작 전 고정 분모 4

| ID | 문서 위치·관찰 | 서비스 적용 · 충족 조건 | 증거 위치 |
|---|---|---|---|
| R-01 | R · Prompt · 기기가 아래에서 위로 등장 | 폰 wrapper가 아래에서 위로 이동하며 등장. 거리·길이는 motion.md 1~3장의 토큰을 사용 | STORYBOARD 각 장면; 이후 영상의 등장 구간과 중간 프레임 |
| R-02 | R · Prompt · 상승 후 부드러운 감속 | `motion-enter`로 감속하며 정착, 바운스 없음. R의 cubic과 동일 곡선이라고 주장하지 않음 | VALUES의 곡선 연결, 실제 상승 구간 재생 |
| R-03 | R · Prompt · 기기 정착 후 알림 카드 표시 | 폰 등장 완료 뒤 기존 parts의 wrapper를 표시. 최초 카드가 폰 정착보다 먼저 시작하면 미충족 | 타임라인 이벤트와 실제 영상 |
| R-04 | R · Prompt · 카드가 시차를 두고 위에서 내려옴 | 같은 묶음의 기존 parts 두 개가 `motion-stagger-item` 시차로 하강 등장. 거리 크기는 `motion-distance-enter` 재사용 | 타임라인과 두 카드의 중간 프레임 |

네 항목은 경로, 속도 형태, 요소 간 선후, 반복 항목 간 시차를 각각 검증한다. 계획 반영과 실제 반영을 구분한다.
반영률 = 충족 항목 수 / 4 × 100. 실제 영상에서 3개 이상 충족해야 게이트를 통과한다. 아직 영상이 없으므로 실측 반영률은 미산출이다.

## 채택하지 않는 특징

R의 원근 기울기·동적 스케일·화면 밖 상승폭·독자적인 동작 시간은 서비스 모션 수치가 미정이므로 채택하지 않는다.
실제 기기 외형·노치·배경 색·폰트·블러·새 알림 UI도 가져오지 않는다. 기존 parts를 사용하며 알림 내용은 만들지 않는다.
원본의 장면 전체 길이와 간격 숫자를 서비스 토큰으로 혼입하지 않는다. 위 제외 범위는 제작 전에 고정했다.

- `mission-card.html` 확인: 원본 진행률과 마감 문구가 포함된 고정 카드. 이번 영상에서 날짜·진행 수치를 새로 만들거나 현재 데이터라고 설명하지 않는다.
- `button-submit.html`의 `submit`과 `view-assets` 상태만 사용한다. `badge-approved.html`은 원본 형태 유지.
- 장면표 단계에서 src 밖 UI는 계획하지 않는다. 실제 겹침·가독성은 스냅보드에서 별도 검수한다.
