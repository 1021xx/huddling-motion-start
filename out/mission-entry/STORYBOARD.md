# 장면표 — v1 · A 승인

사용자 답변 `A / 읽는 시간 규칙 허용`으로 A · 따라가기 선택. B/C는 비교 이력이며 제작하지 않는다.

전체 15초를 설명 단위 셋으로 균등 분할한 후보다. 각 구간 5초는 BRIEF 전체 길이 / 설명 단위 수에서 계산한 **편집 계획**이다.
이 파일의 시각 배치와 문구는 영상별 제안이며 공통 docs에 복사하지 않는다.
모든 안은 R-01~04를 목표로 한다. 실제 반영률·가독성은 후속 이미지와 재생 검수 전까지 확정하지 않는다.

## 공통 표현·수치 근거

- 카메라: 고정. 피사체 회전·동적 스케일 없음(`docs/motion.md` 5장).
- 폰: `docs/video.md` 4장의 프레임. 원본 화면 비율을 유지한다. 폰의 화면 내 크기·배치는 src의 비율과 카드 정렬을 근거로 스냅보드에서 계산·검증한다.
- 일반 등장: `motion-enter`; 카드의 이동은 `motion-distance-enter`의 반대 방향 부호를 사용해 위에서 아래로 정착한다.
- 승인 배지: `motion-emphasis`; 완전한 퇴장: `motion-exit`; 단순 문구/상태 교체: `motion-change`.
- 카드와 버튼은 src 원본 그대로의 별도 wrapper. PNG 내부 요소를 잘라 움직이거나 원본 위에 중복 배지·버튼을 그리지 않는다.
- 영상 헤드라인: `video-headline`; 보조 문구: `video-body`; 엔드 문구: 같은 영상 글자 체계. src의 UI처럼 꾸미지 않는다.
- 화면 밖 좌표·특별한 확대율·장식·새 그림자는 추가하지 않는다. 모든 최종 위치와 균일 배율은 builder가 VALUES에 근거를 남기고 critic이 스냅보드에서 확인한다.
- R의 카드 묶음은 기존 부품으로 대체한다. 폰 정착 뒤 카드, 이어 시차를 둔 버튼 또는 로고가 등장한다. 원본 부품의 크기 비율과 색·글자를 유지한다.

## 미정 해소 — 읽는 시간 규칙 승인

사용자가 아래 계산 규칙을 승인했고 `docs/motion.md` 4장에 등록했다. 장면별 이벤트와 계산 근거는 VALUES.md를 따른다.

- 이름: `motion-hold-readable` (계산 규칙).
- 후보 값: `장면 종료 − motion-exit.duration − 마지막 등장 완료 시점` ms. 마지막 장면은 영상 끝까지 유지하므로 `장면 종료 − 마지막 등장 완료 시점` ms.
- 목적: 승인된 15초 안에서 등장 이후 문구와 UI 요약을 읽는 시간을 확보한다.
- 출처: BRIEF 전체 길이와 이 장면표의 구간 분할, 기존 motion 토큰의 합·차로 계산한 **서비스 제안**. 레퍼런스 실측값 없음.
- 기존 토큰으로 부족한 이유: 기존 duration은 애니메이션 시간이고 읽기용 hold가 아니다.
- 승인 후 처리: 계산 규칙만 motion.md 4장에 등록한다. 장면별 시간·순서는 이 영상 장면표와 VALUES에만 둔다.
- 구체적인 장면별 값은 선택한 안의 이벤트와 출력 프레임 격자를 확정해 계산한다. 임의의 새로운 애니메이션 길이는 만들지 않는다.

장면표 A와 위 규칙의 승인을 APPROVALS.md에 기록했다. 다음은 스냅보드 승인 B다.
