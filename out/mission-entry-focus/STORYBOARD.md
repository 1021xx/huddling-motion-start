# 장면표 개편

후보 A: 행동 연결 — 미션 카드 → 제출 버튼 → 승인 결과. 이전 진단에서 제안했고 사용자가 “응 그러면 … 다시 작업해줘”로 진행 지시한 방향.
후보 B: 결과 먼저 — 승인 → 참여 과정. 현재 요청의 순차 이해보다 결과 강조에 적합.
후보 C: 문구 중심 — 확인·제출·등록을 큰 글자로 연결. 실제 서비스 맥락이 약해져 미채택.

채택 A. 전체 15초를 도입/행동/결과의 3단위로 분할. 기존 5초 균등 배분을 답습하지 않도록 편집 구간은 0–4초 / 4–9초 / 9–15초로 제안. 이는 애니메이션 duration이 아닌 전체 길이 내 편집 계획.
1. 오프닝에 폰을 한 번만 소개하고 감속 정착 후 미션카드를 제시. 스냅보드 01은 카드로 시선이 넘어간 정착 상태.
2. 미션카드 퇴장 후 제목과 제출 버튼을 순차 강조. 버튼 입력의 실제 UI 피드백 범위만 사용. 파일첨부/입력 상태를 상상하지 않음.
3. “검토 후”를 먼저 제시해 시간 경과를 구분. 승인배지 → 결과문구 → 내 자산 버튼 → 로고 순서로 도착.

모션: 기존 enter 240ms / exit·change 150ms / feedback 70ms / emphasis 400ms, 기존 베지어, 등장 16px, 시차 110ms 사용. 장면 첫 0.6초에 전부 나타내지 않고 의미 단위별 편집 비트로 분산. 동적 스케일·회전·반복 장식은 계획하지 않음.
스냅보드 승인 뒤 실제 비트별 읽는 시간을 배분하고 검수한다. 정적 시안은 동작 검증을 대신하지 않는다.
