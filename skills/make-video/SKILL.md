# make-video

프로젝트 루트의 `CLAUDE.md`를 읽는다. 상대 경로의 기준은 프로젝트 루트다. 아래 역할 문서를 명시적으로 읽어 순서대로 실행한다.
이 스킬은 docs의 기준값을 보관하지 않는다. 작업마다 원문 해당 장을 확인한다.

## 기준 찾아보기

| 작업 | 읽을 곳 |
|---|---|
| 색·글자·원본 크기 | `docs/design.md` 1~4장 |
| 사용 가능한 화면·부품·자산 | `docs/design.md` 6장, 실제 `src/screens/`, `src/parts/`, `src/assets/` |
| 길이·곡선·Semantic | `docs/motion.md` 1~2장 |
| 부품별 모션 | `docs/motion.md` 3장 |
| 머무름·카메라·새 후보 | `docs/motion.md` 4~5장 |
| 출력·영상 글자·배경·폰·parts | `docs/video.md` 1~5장 |
| Hyperframes 제작·렌더 | `.agents/skills/hyperframes/SKILL.md`와 해당 작업의 참조 문서 |

## BRIEF

“모션 만들자”로 시작하면 사용자에게 다음 세 가지만 묻는다. 이미 답한 내용은 재질문하지 않는다.

- 무엇을 보여주거나 전달할까요?
- 몇 초 영상인가요?
- 어떤 레퍼런스를 사용할까요? 링크 또는 파일을 주세요.

답은 `out/<영상이름>/BRIEF.md`에 기록한다. 영상 이름은 내용으로 짧게 정하고 기존 폴더와 충돌하지 않게 한다. BRIEF와 결과는 다른 영상 폴더와 섞지 않는다.
받은 참고 파일은 `references/<영상이름>/`에만 저장하고 BRIEF에서 연결한다. 원본 링크도 보존한다.
무응답을 승인으로 취급하지 않는다. 핵심 답이 빠졌으면 그 항목만 확인한다.

## 제작과 승인

1. `agents/art-director.md`: 레퍼런스를 확인하고 `REFERENCE.md` 작성. 구성 뼈대 하나와 보조 역할, 체크 항목 ID·충족 조건을 고정한다.
2. `agents/director.md`: `STORYBOARD.md`에 장면표 세 안을 정리한다. 먼저 요약을 보여주고 critic 판정 후 사용자가 하나를 고른다. 이것이 **승인 A**다.
3. `agents/builder.md`: 선택된 안으로 실제 자산의 스냅보드를 만든다. 먼저 이미지를 보여주고 critic 판정 후 사용자 승인을 기다린다. 이것이 **승인 B**다.
4. 승인 B 후 builder가 영상을 구현한다. 실제 미리보기와 검증 프레임을 먼저 보여주고 critic 판정·필요한 수정을 거쳐 최종 렌더를 검수·전달한다. 추가 정례 승인을 만들지 않는다.

critic은 각 검수 시 `agents/critic.md`를 읽고 판정만 수행한다. 수정은 해당 산출물의 담당 역할에게 되돌린다.
장면표 PASS는 스냅보드 제작의 사람 승인을 대신하지 않고, 스냅보드 PASS도 영상 제작의 사람 승인을 대신하지 않는다.
진행 담당은 `APPROVALS.md`에 선택안·대상 버전·사용자의 실제 답변을 기록한다. “기본값”은 제안된 기본값을 선택한 것으로 기록한다.
승인 대상의 구성·룩을 바꿨다면 해당 승인을 다시 받는다. 승인 기록 없이 완료했다고 보고하지 않는다.

## 통과 게이트

- 문서 밖 숫자 **0개**: 시각·모션 수치는 docs의 토큰 또는 명시된 계산을 추적할 수 있어야 한다. 레퍼런스에 숫자가 있다는 이유만으로 허용하지 않는다.
- src 밖 UI **0개**: 화면·부품·상태의 원본 경로와 요소를 확인한다. 별도 영상 카피는 UI로 세지 않고 `docs/video.md` 1·3장을 검수한다.
- 레퍼런스 반영 **60% 이상**: `충족 항목 수 / 고정한 전체 항목 수 × 100`. 항목은 동일 가중치로 이진 판정하며 충족 조건 전체를 만족해야 센다.
- 놓는 위치·정렬은 실제 화면과 부품의 관찰 근거가 있으면 허용한다. 경로·요소·정렬 관계와 필요한 계산식을 `VALUES.md`에 남긴다. 무근거 좌표는 통과시키지 않는다.

숫자 게이트는 콘텐츠의 수익·진행률 같은 원본 데이터나 BRIEF에서 사용자가 정한 전체 길이를 임의의 모션 상수로 세지 않는다. 원본/BRIEF 필드를 증명해야 한다.
장면 시작·종료와 프레임 번호는 승인된 전체 길이·장면표·문서 출력 기준에서 계산해 기록한다. 애니메이션 길이·머무름·곡선·스케일을 일정 계산값으로 위장하지 않는다.
HTML의 좌표계·투명도 끝값 등 구현에 필요한 값은 의미와 계산 근거를 남긴다. 새로운 룩·움직임의 강도를 정하는 값이라면 “새 후보” 절차를 적용한다.
후보 수치는 docs에 반영되기 전까지 사용하지 않는다. 승인 요청·문서 변경이 필요하면 명시적으로 사용자에게 알린다.

체크 항목은 구성·구도·카메라·전환·글자 배치 중 실제 레퍼런스에서 확인된 특징으로 정한다. docs와 충돌하는 특징은 고정 전에 제외 사유를 적는다.
장면표에서는 계획 근거, 스냅보드에서는 정적 근거, 최종 영상에서는 실제 재생 근거로 판정한다. 미검증 동작은 보류로 표시하고 최종 영상에서 확인한다.
전체 항목이 없거나 레퍼런스를 확인하지 못했으면 반영률을 산출하지 않고 HOLD한다. 평가 가능한 레퍼런스를 요청한다.
실패를 피하려고 체크 항목을 삭제·분할·완화하지 않는다. 레퍼런스나 요구 변경으로 바꿔야 하면 사용자에게 변경을 알리고 관련 승인부터 다시 받는다.

## 공개·실패·완료

결과를 먼저 보여주고 **한 줄 판정**을 붙인다. 세부 증거는 `REVIEW.md`에 단계·항목 ID·파일·시점과 함께 누적한다.
진행 담당은 `단계 + 검사 항목 ID`별 연속 실패 횟수를 기록한다. 같은 곳에서 **두 번** 실패하면 자동 수정을 멈추고 실패 근거·가능한 선택지를 보여주며 사용자에게 묻는다.
다른 항목을 고쳤다고 해당 횟수를 초기화하지 않는다. 해당 항목이 실제 재검수에서 통과했을 때만 연속 실패를 해제한다. HOLD는 실패 횟수를 지우지 않는다.
증거·승인·새 후보 답이 필요한 HOLD에서도 의존 작업을 진행하지 않는다. 독립적으로 가능한 작업만 이어 간다.
최종 PASS에는 실제 렌더 파일 재생/프레임 검수와 모든 게이트 근거가 필요하다. 렌더 실패나 확인 불가를 완료로 처리하지 않는다.
완료 시 재생 가능한 결과, 로컬 파일 링크, 한 줄 판정을 제공한다. 제작 승인만으로 외부에 게시하지 않는다.
