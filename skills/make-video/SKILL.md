# 서비스 모션 영상 제작

경로는 프로젝트 루트 기준이다. CLAUDE.md와 해당 역할 문서를 먼저 읽는다.

## 판단 기준

| 구분 | 읽을 문서 | 판단 |
|---|---|---|
| 브랜드·원본 | docs/brand-rules.md, docs/design.md, src/ | 정체성·서비스 사실·UI 원본을 지켰는가 |
| 영상 표현 | docs/motion-direction.md | 목적에 맞는 구도·시선·편집을 설계했는가 |
| 기본 도구 | docs/motion.md, docs/video.md | 사용할 기본값을 선택. 모든 장면에 강제하지 않음 |
| 구현 예시 | docs/motion-examples.md | 필요할 때 참고. 숫자·순서 복제 의무 없음 |
| 품질 | docs/quality-review.md | 정적 디자인·움직임·기술을 별도로 검수 |
| 렌더 | .agents/skills/hyperframes/SKILL.md | 타임라인 계약·실제 프레임·파일 확인 |

## 브리프

목적·전체 길이·참고 자료와 사용자의 기존 선호를 BRIEF.md에 정리한다. 이미 답한 내용을 재질문하지 않는다. 핵심 정보가 없으면 필요한 항목만 확인한다. 파일은 out/<영상이름>/, 받은 참고 파일은 references/<영상이름>/에 보관하며 기존 결과를 보존한다.

## 작업과 승인

1. art-director: 참고 영상을 실제로 확인하고 관찰·해석·서비스용 선택을 분리해 REFERENCE.md에 기록한다. 구도·깊이·여백·타이포 위계·연결 원리를 다룬다. 실제 영상을 보지 못했다면 프롬프트 설명을 영상 관찰로 대체하지 않는다.
2. director: 접근이 다른 장면표 후보를 제시하고 선택된 안을 STORYBOARD.md에 정리한다. 장면표 선택이 승인 A다. 사용자가 이미 방향을 선택했다면 같은 선택을 다시 요구하지 않는다.
3. builder: 실제 자산으로 대표 정착 구도와 중요한 전환 상태를 스냅보드로 만든다. critic이 정적 디자인을 평가한다. 정적 구도가 약하면 모션을 붙이기 전에 수정한다. 스냅보드 확인이 승인 B다.
4. builder: 승인된 범위에서 타임라인을 구현하고 미리보기·최종 렌더를 검수한다. critic은 움직임·편집과 기술을 별도로 확인한다. 추가 정례 승인 단계는 만들지 않는다.

사용자가 중간 승인 없이 제작하라고 지시했거나 이미 해당 범위를 승인했다면 그 지시에 따라 진행하고 근거를 APPROVALS.md에 정확히 기록한다. 무응답이나 검수 통과를 사용자 승인으로 간주하지 않는다. 실제 지시가 없는 승인 생략을 기록하지 않는다.

## 연출 재량과 기록

문서 밖 연출 숫자 자체는 실패 조건이 아니다. 배치·타이포 크기·그림자·카메라·곡선·동작 길이·읽기 시간은 목표에 맞게 선택하고 VALUES.md에 대상·값·목적·검수 결과를 적는다. UI 내부 스타일과 브랜드 기본 토큰은 바꾸지 않는다. 서비스 사실이나 명시적 조건을 바꿔야 할 때 해당 사항만 확인한다.

원본 UI와 별도 영상 그래픽을 구분한다. 새 설명 그래픽은 허용하되 실제 기능·상태로 오인시키지 않는다. 영상 배치는 원본 UI 좌표를 복제할 필요가 없으며 정렬·여백·가독성으로 설명한다.

## 검수와 완료

quality-review.md에 따라 브랜드·사실 / 정적 디자인 / 움직임·편집 / 기술을 따로 판정한다. 단순 효과 개수나 일률적인 참고 반영률은 통과 조건으로 쓰지 않는다. REFERENCE.md의 핵심 원리가 어떻게 구현됐는지는 실제 시점·프레임으로 설명한다.

REVIEW.md에 문제 ID·근거·수정 결과·미검증 범위를 남긴다. 같은 문제가 반복되면 원인을 다시 진단하고 접근을 바꾼다. 사용자가 결정해야 하는 취향·조건 충돌이 있을 때 구체적인 선택지를 제시한다. 미검증을 PASS로 표시하지 않는다.

최종 결과는 실제 인코딩 파일에서 규격·길이·대표 프레임·주요 전환을 확인한다. 재생을 직접 확인하지 않았다면 프레임 검수라고 적는다. 결과 파일과 미리보기를 전달하고 외부 업로드·게시에는 별도 권한을 확인한다.
